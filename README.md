# LLM Radar · 个人大模型决策台

把 **LMArena / Artificial Analysis / llm-stats / LiveBench** 四个评测源按 **6 大类 17 子类**并排，
**不合成总分**，只呈现源内名次与跨源分歧。

它回答的是一个很具体的问题：**这个模型在某件具体的事上排第几，以及不同榜单对这件"事"的看法差多少？**

页面本身零依赖、无构建。`index.html` 用相对路径引用 CSS/JS/数据，双击即可打开，也能直接扔上静态托管。

---

## 一、为什么没有总分

这是本项目最核心的一个决定 —— 不是没做，是刻意不做。

四个源的分数是**四种不同的尺子**：

| 源 | 指标 | 量纲 |
|---|---|---|
| LMArena | Arena Elo | 相对胜负的 Elo（1506 ± 5） |
| Artificial Analysis | Intelligence Index | 自建聚合指数 |
| llm-stats | LLM Stats Score | TrueSkill μ−3σ |
| LiveBench | Overall | 0–100 客观题正确率 |

它们之间**没有任何可验证的换算关系**。任何"平均分"都等于把 Elo 1506 和正确率 73% 直接相加 ——
算式跑得通，但那个数字不指代世界上任何东西。

所以页面上只出现三种量：

| 量 | 含义 | 为什么可以比 |
|---|---|---|
| **名次** | 1 = 该榜第一 | 无量纲，是唯一能跨源并列的量 |
| **原始分** | 各源自己的分数，原样保留 | 只放在 tooltip 与详情表，并标明来源与单位 |
| **跨源分歧度** | 该模型在各源**名次百分位**的极差（0–100） | 全程在"名次"体系内计算，不碰量纲 |

分歧度的分母用**本页展示范围 N**，而不是源站全库规模 —— 用全库会被大盘稀释：
LMArena 文本榜收录 402 个模型，名次 1 与名次 30 的百分位只差 7 个点，分歧度会被压成一条平线。

## 二、快速开始

```bash
git clone https://github.com/Lavie-purple/llm-radar.git
cd llm-radar
```

**只是看页面**：直接双击 `index.html`。数据通过 `data/app.json.js`（而非 `fetch`）加载，
所以 `file://` 协议下也能正常工作，不会触发 CORS。

**想跑数据管道**（重新抓取四个源）：

```bash
python tools/run_all.py              # 全流程
python tools/run_all.py --only aa    # 只跑指定源
python tools/run_all.py --no-snapshot --no-selftest --no-health   # 只抓取与合成
```

**依赖**

- **Python 侧零第三方依赖。** `tools/*.py` 只 import 标准库（`urllib` / `json` / `statistics` /
  `csv` …），不需要 `pip install` 任何东西。开发环境为 Python 3.13。
- **`selftest.js` 只用 Node 内置模块**（`fs` / `path` / `vm`），开箱即跑。
- **`visual_check.js` 与 `check_deploy.js` 需要装包**，它们都要跑真实浏览器：
  ```bash
  npm i playwright && npx playwright install chromium
  ```
- 抓取环节要联网；无网络时管道会在抓取步失败并**保留上一版数据**（不会覆盖出空页面）。
  `check_deploy.js` 也联网（打线上），但它只读不写，离线时直接报"取不到"而不是改数据。

## 三、页面怎么读

**两种视图**

- **跨榜名次矩阵** —— 行是模型，列是「源 × 子类」。**每一格是该模型在该榜自己的名次**，
  格内不出现分数，避免把 Elo 和百分比混为一谈。
- **大类详情** —— 按 6 大类展开，每个子类一行，把四个源的原始分并排列出。

**交互**

| 操作 | 效果 |
|---|---|
| 点列头 | 按该列排序；再点切升/降序；第三次恢复默认 |
| 悬停格子 | 原始分、全榜位置、票数/σ/证据局数、来源、覆盖榜数、分歧度 |
| 悬停模型名 | **发布日期与「新」判定** —— 包含「为什么这个模型没有标识」 |
| 模型名前的 `新` | 该模型**最近 30 天内发布**。数据只来自 llm-stats，窗口可用 `?new=NN` 改（`?new=0` 关掉） |
| 点击行 | 打开该模型的完整卡片（全维度明细 + 走势） |
| 顶部搜索 | 按模型名 / 厂商过滤 |
| 开源筛选 | 全部 / 开源 / 闭源 |
| 只看覆盖 ≥3 榜 | 过滤掉长尾 |
| 性价比 ÷ 价格 | 名次 × $/1k 对话排序。⚠️ 价格跨度有三个数量级而名次只有一个，结果会明显偏向便宜的小模型，看纯实力时请关掉 |
| 数据变化闪烁 | 相比你上次打开时**档位真的变了**的格子会闪一下 |

**怎么读数字**

- **名次**：1 = 该榜第一。空点 `·` 表示未进本页收录范围或未参评。
- **分歧度**：越高说明该模型越依赖特定评测口径。带「单源」标记的子类只有一个源，
  分歧度无从计算，留空是正常的。
- **「新」标识**：模型名前的 `新` = 距今 ≤ 30 天发布（按**数据生成时间**算，不是按你打开页面的时刻）。
  **没有这个标识 ≠ 模型不新** —— 四个源里只有 llm-stats 提供发布日期，查不到的名字就没有标识，
  悬停模型名会写明是「在窗口内」「已出窗口」还是「llm-stats 无此模型」。
- 每个名次的来源都在列头、tooltip 与详情卡片里写明 —— **不出现无出处的数字**。

## 四、数据源

| 源 | 站内规模（源站自述） | 抓取方式 | 备注 |
|---|---|---|---|
| **LMArena** | 12 榜 / 340 行 | 第三方中文镜像 `arena.atease.dev` 的 RSC payload | 官方无公开 API，这是目前唯一的自动通道 |
| **Artificial Analysis** | 272 模型 | `leaderboards/models` 页面内嵌 RSC payload | 免 API key；官方 API 需付费 key |
| **llm-stats** | 392 模型 / 55 分类 | 站点内嵌数据 | 四个源里**唯一提供模型发布日期**（`release_date`，390/392 有值）的源，「新」标识完全依赖它 |
| **LiveBench** | 58 模型 / 7 类 | `livebench.ai` + GitHub 原始文件 | release 半年一刷，缺新模型是正常的 |

**当前快照规模** —— 下面的数字全部由 `python tools/stat_app.py` 输出，随数据更新变化：

- 6 大类 / 17 子类（chat 4、general 5、code 2、agent 1、image 2、video 3）
- 每个子类收录前 **30** 名
- **模型库 193 个**，其中开源 42 个、覆盖 ≥3 个榜的 43 个
- 其中 **114 个进入矩阵** —— 入选条件是**覆盖 ≥2 个榜，或在单榜排进前 10**；
  其余 79 个只在「大类详情」视图里按子类出现
- 矩阵 114 × 17 = **1938 格**，有值 379 格、空位 1559 格（**填充率 19.6%**）。
  空位多是正常的 —— 不是每个模型都参加了每一个榜
- **「新」标识**（窗口 **30 天**）：矩阵里 **8 行**亮标；有发布日期的 45 行、无日期的 69 行。
  各窗口的亮标数也由 `stat_app.py` 一并打印（14 天 1 行 / **30 天 8 行** / 45 天 13 行 /
  60 天 18 行 / 90 天 26 行）—— 换窗口前先看这组数，别凭感觉调

**单源子类 7 个**（分歧度必然为空）：
图生网页、文生图、图像编辑、文生视频、图生视频、视频编辑，
以及幻觉控制（两个列同属 AA，故亦为单源）。

## 五、数据管道

```
tools/run_all.py
  │
  ├─ 1. 抓取    fetch_lmarena.py / fetch_aa.py / fetch_llmstats.py / fetch_livebench.py
  │             → data/{lmarena,aa,llmstats,livebench}.json
  │
  ├─ 2. 体检    health.py            抓取量对比历史中位数，缩水即失败
  │
  ├─ 3. 合成    build_app.py         四源合并 → data/app.json（+ app.json.js）
  │              └ normalize.py      模型名归一化到 canonical family id
  │              └ 落 releasedAt     取自 llm-stats 的 release_date，供「新」标识用
  │
  ├─ 4. 自检    selftest.js          236 条断言
  │
  ├─ 5. 存档    snapshot.py          → snapshots/<时间戳>/
  │
  └─ 6. 走势    build_history.py     扫全部快照重算 → data/history.json（+ .js）
```

**推完之后**（刻意**不**放进 `run_all.py`：每日管道不该因为外部站点不可达就失败）

```bash
node tools/check_deploy.js --wait=120   # 等 Pages 追平，再逐字节比对 + 线上真渲染
```

**三处设计上的保守**（都是被真实故障教出来的）：

- **抓取器全绿 ≠ 抓全了。** 源站改版最典型的症状恰恰是「HTTP 200 + 解析无异常 + 结果为空」。
  所以第 2 步单独体检：与最近几次的**中位数**比（不用上次值，避免单次抖动误报；趋势性塌缩才该报警），
  缩水即失败。**缩水才是失败，变大只是警告** —— 源站新增一个大类会让行数合法暴涨，
  拿它挡住当天的更新纯属误报。
- **体检不过就不覆盖。** 第 3 步只在「四源全成功 **且** 体检通过」时才重建 `app.json`，
  否则保留上一版可用数据，而不是拿半份数据覆盖出一个看着正常的空页面。
- **发布日期的匹配不用相似度兜底。** 「新」标识要靠 llm-stats 的 `release_date`，而模型名跨源不一致，
  只能靠归一化后的 id 对齐。**故意不写模糊匹配**：实测 `Veo 3 ≈ o3`（0.67）、
  `Qwen 3.8 ≈ Qwen3.5-0.8B`（0.80）、`Seedream 5.0 Pro ≈ Seed 2.0 Pro`（0.73）——
  名字很像但根本不是一个东西，猜错等于给模型安上别人的发布日期。**宁可没有标识。**

## 七、守卫与自检

改完代码**不要靠看**。这个项目有四层，每一层都能独立抓 bug。
前三层证明「我这份源码是对的」，第四层证明**「线上跑的就是这一份」**。

```bash
node tools/selftest.js          # 236 条断言：数据管道 + 前端逻辑（纯内置模块）
node tools/visual_check.js      # 144 项检查：需先起 8758 端口 + 已装 playwright
python tools/falsify.py         # 17 条证伪用例（退出码 0=全红通过 / 1=有用例失效 / 2=开跑前体检不过）
node tools/check_deploy.js      # 线上部署核验：推完跑一次，本地 vs 线上逐字节比对 + 线上真渲染
node tools/check_deploy.js --wait=120   # 推完立刻跑：等线上追平，最多等 120s
FALSIFY_NET=1 python tools/falsify.py   # 连联网用例一起证伪（含 check_deploy）
```

起服务：`python -m http.server 8758 -d .`（`visual_check.js` 会打开真实 Chromium 逐项量 DOM。
`check_deploy.js` **不用**先起服务 —— 它自己起一个随机端口的静态服务做本地渲染对照）

**为什么是四层**

1. **`selftest.js`（236 条）** —— 用 DOM 桩把页面逻辑跑起来，覆盖数据管道的每个环节与
   前端渲染分支。**依赖"数据随时间积累"的功能（如走势线）必须在夹具下测**：
   真实数据只有一天时，那条活跃路径根本不会执行，断言看起来"已覆盖"其实是空转。
   它用 `newHarness(historySrc, {patch, search})` 开第二套环境喂合成夹具 ——
   `patch` 可在渲染前改 `APP`（测「新」标识的窗口边界），`search` 可伪造 `?new=NN`。

2. **`visual_check.js`（144 项）** —— 起真实浏览器**量 DOM**，而不是看截图。
   量的是：表格列宽是否把内容压成逐字换行、搜索框实际能显示几个字、
   对比度是否过 AA、悬停时色阶是否还保持秩序、悬停是否恰好高亮一行、
   超宽屏两栏是否等高、有无横向溢出、**插入「新」徽章后有没有把模型名挤成省略号**。

   > **这个项目里的两个真 bug 都是"看着正常、量出来才现原形"** ——
   > 所以「截图看着没问题」不构成通过依据。

3. **`falsify.py`（17 条）** —— **证伪**：把被守卫保护的那行代码真的拆掉，看守卫是否变红。
   锚点直接绑在源码字符串上，**「锚点失效」和「拆了还全绿」都算失败**（退出码 1），
   防止过期用例长期假装通过。

   > 写这条工具的直接原因：曾有一条守卫**是假的** —— 断言「动画结束后颜色回到档位色」，
   > 但 `animation-fill-mode` 默认 `none`，动画结束后元素本就会回到自身样式，
   > 于是加不加显式 `to` 都能通过。改用 `getKeyframes()` 读隐式终值后，证伪才精确变红。

   ⚠️ **它会真的改源码再还原，所以自己也会成为故障源。** 被 Ctrl-C / SIGTERM 打断时
   （无 TTY 环境下超时杀进程也算）`finally` 不保证执行 → 替换留在源码里没人还原。
   这个状态很阴：下次跑会报一串「锚点失效」，把**「上次被打断」伪装成「用例过期」**，
   真正的死因就看不见了。实测踩过：两次被打断分别留下 `if (!rd) return 0;`（应为 `return null`）
   与 `那是随机高亮`（应为「那是相对你上次打开时档位变了」），当时只当是锚点腐烂。
   现在加了两道防护 —— **信号处理器收到信号先还原再退出（130）**，
   以及**开跑前体检全部锚点、缺一条就拒绝开跑（2）**。

   ⚠️ **另一个更隐蔽的陷阱：「一条 FAIL 都没有」不等于「守卫是假的」。** 工具半途崩了、
   起不来、或页面没加载成功，同样一条 FAIL 都不打印 —— 于是偶发崩溃会被误报成
   **「这条断言是假的」**，把人引去改一条本来没问题的断言。实测踩过：一次完整跑里
   「徽章不再用 llm-stats 源色」报「仍然全绿」，但单独跑、以及连跑它前面那条再跑它，
   **两次都精确变红**。所以判定必须三分：`变红` / `仍然全绿（假守卫）` /
   **`没跑完（结论不作数）`**。做法是要求被测工具打出**末尾必定出现**的收尾汇总
   （`selftest.js` 的 `／ FAIL `、`visual_check.js` 的 `截图目录：`），打不出来就不给结论。
   顺带修掉一个 Windows 坑：`subprocess(..., text=True)` 默认按本地编码解码，
   而 node 输出的是 UTF-8 —— 必须显式 `encoding='utf-8', errors='replace'`。

   ⚠️ **靶子不止 `radar.js` / `radar.css` —— `tools/visual_check.js` 自己也是靶子。**
   守卫也会写出没信息量的产物，同样要被证伪。实测：`shot('17-newbadge')` 原先是整屏截图，
   与 `06-trend-pending` / `14-flash` 拍出来的 PNG **md5 完全相同**（都是「矩阵停在顶部」那一屏），
   等于什么也没记录 —— 而「靠形状传意」的元素（17px 宽的徽章）恰恰只能靠特写肉眼看。
   现在改成按首列按钮的 rect 裁框，并加了「裁剪框必须收在首列之内（不是整屏）」的断言守着它。

4. **`check_deploy.js`（38 项；带 `GITHUB_TOKEN` 时 53 项）** —— 前三层**全部在本地跑**，它们证明「源码是对的」，
   证明不了**「线上跑的就是这一份」**：Pages 可能还在部署、可能部署失败、
   Jekyll 可能吃掉某个文件（`_` 开头的目录线上就是 404）、也可能推了代码但线上还是上一版数据。
   这一层补的就是这段。推完 `git push` 跑一次：

   - **静态文件逐字节比对**：`index.html` + `scripts/*.js` + `styles/*.css` + `data/*.js`
     （清单由目录扫描得出，新增样式/脚本会自动进清单，不会因为忘了改脚本而漏检）。
     不一致时报出**首个不同处的行号 + 两侧原文**，给的是能定位的线索而不是一句"不一样"。
   - **线上数据自洽**：窗口默认值、带发布日期的模型数、`generatedAt` 与本地一致。
   - **线上真渲染**：无头浏览器打开线上页，核对矩阵行数、**有值格子数**、「新」徽章数
     —— 这三个数都用**独立重算**（另写一遍的口径，同 `verify_lmarena.py` 的思路）来比，
     而不是读页面上现成的值互相对照。
   - **本地渲染对照**：自己起一个随机端口的静态服务，把本地渲染出的
     `rows / cells / miss / filled / badges / models / win / gen / title / 脚注 / 已知缺口`
     逐项与线上对表。**这一项才是「线上真的和我本地一样」的直接证据。**
   - **线上 URL 覆盖实测**：`?new=0` 必须变 0 个徽章，`?new=3650` 必须放宽到全部有日期的行
     —— 证明运行时覆盖在**线上那份**里也好使，而不只是源码里有这行字。
   - **Pages 构建结论**（可选，需 `GITHUB_TOKEN`）：读 `/actions/runs` 的 **job/step 级**结论。

   ⚠️ **两个必须记住的坑，都写进源码注释了：**

   1. **线上文件比本地每行少 1 字节** —— 仓库里是 CRLF，Pages 出去是 LF。
      实测 `scripts/radar.js` 本地 68571 字节 / 1307 个 CRLF，线上 67264 字节 / 0 个 CRLF，
      **差值恰好 = 行数**。不先做行尾归一化就直接比，会把「同一份文件」全部判成不一致。
   2. **不要拿 `GET /pages` 或 `/pages/builds/latest` 判断部署成败** —— 那是 legacy 端点，
      会把「连推两次时前一次 deploy 被取消」记成 failed 且**不自我复位**，长期假报 `errored`
      （本仓库真踩过）。权威信号是 `/actions/runs` 里 `pages build and deployment` 的 job/step 结论。
      脚本走后者，并在输出里显式写「不看 `/pages`」。

   ⚠️ **它内部不起子进程。** 本机（WorkBuddy 沙箱）里 `execSync` / `execFileSync`
   一律抛 `spawnSync ... EBUSY` —— 连 `cmd.exe` 和 `git` 都起不来。所以取 HEAD 与远端 slug
   是**直接读 `.git/HEAD` / `.git/packed-refs` / `.git/config` 的文本**（也顺带去掉了
   「PATH 上必须有 git」这个隐含依赖）。

   代价：`check_deploy.js` 要联网 + 真浏览器，比前三层慢（实测 25~50s，取决于线上抓取），所以**不进 `run_all.py`**
   （每日管道不该依赖外部站点的可达性），也不进 `falsify.py` 的默认用例
   —— 它那条联网用例挂在 `FALSIFY_NET=1` 后面。

## 八、改代码前必读

这些都是**实测踩出来的**，不是理论推测。违反任何一条都会引入肉眼看不见的回归。

**硬规则**

1. **不合成任何跨源总分。** 四个源量纲不可换算，只做源内名次与源内百分位。
2. **跨源分歧度的分母是本页展示范围 N**，不是全库规模。
3. **每个名次都要能追溯来源。** 列头、tooltip、卡片都必须写明该值来自哪个源。
4. **成本不跨源换算**，各源各写各的单位（$/M token、$/任务、$/成功任务）。

**已知陷阱**

- **`transition` 在本项目里永不触发，必须用 `@keyframes`。**
  `renderMatrix()` 是 `t.innerHTML = h` 整块替换，1938 个格子节点全部销毁重建；
  `transition` 要求「同一个元素」保存前一个值，新元素只有终值。
  实测：给每个 `td` 打身份标记，重渲染后**带标记的 = 0**；而 `@keyframes` 在 1938 个**新建**节点上全部 `running`。
  技巧：`@keyframes` **只写 `from`、省略 `to`**，隐式 `to` 会取元素自身样式值，省得把六个档位色再抄一遍。

- **热力色在 `.cellbtn` 上，不在 `td` 上。** `td.cell` 的计算背景是 `rgba(0,0,0,0)`。
  要改色阶请改 `.q1–.q6`；给 `td` 铺背景对已有热力色无效，只会让空位 `·` 整块显形。

- **色阶 `alpha` 在深色底上有硬上限约 0.55。** 蓝 `#38bdf8` 合成到 `#14181d`、文字 `#e9eef4`：
  `0.30 → 8.23:1`、`0.55 → 4.54:1`（刚好过 AA）、`0.60 → 4.05:1` 破线。
  想靠拉大跨度换区分度，最多到 0.55。

- **悬停提亮会破坏色阶秩序。** 实测像素反解：静止时 `q1 = 0.292`、`q2 = 0.206`；
  用 `brightness(1.5)` 悬停时 `q1 = 0.419`、`q2 = 0.292` —— **悬停中的 q2 等于静止的 q1**，
  一行内的深浅关系在悬停瞬间失效。且 `filter` 连文字一起提亮（`#e9eef4 × 1.5` 直接截断成纯白）。
  现用 `brightness(1.14)` + 模型列左侧 3px 橙条来定位行，不动颜色。

- **`table.matrix` 是 `width:max-content; min-width:100%`，余量按各列 preferred width 的比例瓜分。**
  容器一旦宽于 `max-content`，余量会按比例灌给所有列，而**模型列 preferred 最大所以独吞大头**
  （实测容器 2080→3400 时模型列 411px→671px，整条死白）。
  给 `td` 写 `max-width` **无效**（auto 布局直接无视，实测仍 708px）。
  矩阵宽度因此被**封顶在 ~2100px**；首列宽度必须由 `--colmodel` 固定，否则余量会全灌进首列。

- **往首列塞任何东西，代价是「名字被截断」，不是「换行」。**
  `.mbtn` 是 `flex; gap:8px`，`.mname` 是 `flex:1; white-space:nowrap; text-overflow:ellipsis` ——
  它**永远不会换行**，只会提前变成省略号。所以插入一个元素要吃掉「自身宽度 + 一个新的 8px 间隙」，
  而且**必须用 `scrollWidth > clientWidth` 去量截断，量行高是量不出来的**。
  实测（1600px 视口、首列 306px）：名字富余宽度最小 **36.2px**（`Gemini 3.1 Flash Image [web Search]`）；
  「新」徽章 17px + 间隙 8px = 25px，最小那行仍剩 11px，114 行一个都不会被截断。
  想做 `NEW`（约 37px）或 `新 12d`（约 50px）就会开始截断。

- **给这个表格做浏览器自动化时，要滚的是 `.tablewrap`，不是窗口。**
  矩阵在 `.tablewrap`（`overflow:auto; max-height:74vh`）里自己滚；只滚 `window` 的话，
  目标行仍留在容器裁剪区外，`elementFromPoint` 点不到，鼠标会落到顶栏或 `.wrap` 上。
  还有两个连带坑：`tr.offsetTop` 相对的是 `<table>` 而不是文档（差一整个表头高度），
  要用 `getBoundingClientRect().top + scrollY`；`scroll` 事件派发**晚于**输入事件，
  滚完立刻悬停会被迟到的 `hideTip()` 把提示关掉 —— 所以要先滚、等约 400ms、再动鼠标。
  `visual_check.js` 里的 `hoverTip()` 就是按这三条写的，并且会先断言悬停点确实落在目标按钮上。

- **自检的 DOM 桩 `closest()` 是「选择器字符串全等」匹配。**
  所以 `radar.js` 里要写 `e.target.closest('[data-cell]') || e.target.closest('[data-model]')`，
  **不能**写成复合选择器 `closest('[data-cell], [data-model]')` —— 后者在桩里永远返回 `null`，
  测试会莫名其妙全红（真实浏览器里两者等价）。

**开发循环**

```bash
# 改前端逻辑或数据
node tools/selftest.js

# 改样式（先起 8758 端口）
node tools/visual_check.js

# 写完任何守卫后 —— 必须证明它会在被拆时变红
python tools/falsify.py

# 推完 —— 证明线上跑的就是刚推的这一份（不在 run_all.py 里）
node tools/check_deploy.js --wait=120
```

**本机环境陷阱：Node 里起不了子进程**

- **`execSync` / `execFileSync` 一律抛 `EBUSY`。** 实测连 `cmd.exe` 和 `git` 都 spawn 不起来
  （`spawnSync C:\Windows\system32\cmd.exe EBUSY`）。所以要在 Node 里拿 git 信息，
  得**直接读 `.git/HEAD`、`.git/packed-refs`、`.git/config` 的文本**，而不是调 `git`
  （`check_deploy.js` 就是这么做的，附带好处是不再依赖 PATH 上有没有 git）。
  同理**不要在守卫里用 `child_process`** —— 一旦本机的执行策略变化，守卫会以「跑不完」的形态挂掉，
  而按 `falsify.py` 的三态判定它只会被记成"没跑完"，真正的死因容易被忽略。

## 九、已知缺口

- **图像 / 视频两个大类只有 LMArena 一个源。** AA 的 image / video Elo 是异步加载的，抓不到；
  llm-stats 的图像/视频榜同为客户端渲染。这两个维度**分歧度全部为空**。
- **单个子类只有一个源时，分歧度无法计算**（当前 17 个子类里有 7 个如此），留空属正常。
- **页面上的名次走势是本站自建的。** LMArena / AA / LiveBench 都只提供「当下快照」，
  走势来自对 `snapshots/` 的逐日重算 —— 所以**只能从本站开始抓取的那天算起，再往前的补不回来**，
  且历史只记各榜前 40 名。当前快照只有 1 天，走势线需 ≥2 天才绘制（页面显示「积累中」）。
- **llm-stats 自带的 14 天名次变化被抓了、但前端没用。** 它提供 `rank_delta_14d`，
  抓取器与 `build_app.py` 已完整保留（落成 `delta14d` 字段，当前数据里 276 处字段、23 处有实际值），
  却**从未被读取**。这是一条现成的、比自建快照更早可用的历史信号，属于尚未开发的缺口。
- **「新」标识的覆盖是不完整的。** 四个源里**只有 llm-stats 提供发布日期**，矩阵 114 行里
  只有 45 行查得到（`releasedAt`），其余 69 行在源里根本没有这个模型 —— 它们不带标识，
  **但那不等于它们不新**。好在漏掉的 69 行覆盖榜数全部 ≤3（Flux / Seedance / GPT Image
  这类长尾图像视频模型），头部模型是齐的。窗口默认 30 天，可用 `?new=NN` 覆盖。
  发布日期**不参与任何名次、原始分或分歧度的计算**。
- **同名不同实体不会自动合并。** 矩阵里存在同显示名、不同 id 的条目（例如 `qwen3.8` 覆盖 10 榜、
  `qwen3.8.27b` 覆盖 4 榜，二者都显示为「Qwen 3.8」，只有后者带「新」标识）。
  这是归一化规则的既有边界（`27B` 是参数量，不是版本号），排查时需要人工比对。
- **LMArena 数据取自第三方镜像**（`arena.atease.dev`），非官方站。
- **LiveBench release 半年一刷**，最新版里没有当季新模型，缺值正常。
- **同名模型跨源靠规则归一化**，推理强度变体（High / Max / thinking）已合并为同一条并保留最优名次。
  `normalize.py` 的别名表目前为空，**无法归一的模型会保持独立 id**；
  docstring 里提到的 `check_merge.py`（未匹配清单报告）**尚未实现** —— 排查合并问题时需要人工比对。
- **部署核验只覆盖「页面真正会加载的那 7 个文件」**（`index.html` + `scripts/*.js` +
  `styles/*.css` + `data/*.js`）。仓库里其它文件线上即使 404 也发现不了 —— 比如 `_` 开头的目录
  会被 Jekyll 吃掉（`_legacy/` 线上就是 404），页面不依赖它们，所以不算问题。
  另外字体走 Google Fonts，**跨域请求失败只记账不判错**，避免一个 CDN 抖动把部署判成坏的。
- **每日计划任务未注册**（Windows `schtasks.exe` 被本机安全策略拦截），
  目前靠手动执行 `tools/run_daily.bat`。
